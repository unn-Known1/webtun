## Area 1 — Backend Auth / Session / PIN + WS Binary Protocol + PTY/tmux Lifecycle
**Source:** `server.js` auth, `checkPin`, `TRUST_PROXY`, `ALLOWED_ORIGINS`, WS `0x00/0x01/0x02/0x03`, `tmuxOwnName/tmuxAdoptableNames/ownTmuxSessions/claim`, `ptySessions`, crash semantics.

### Critical
- **[critical] Reflected XSS in preview error via `:port`** — `server.js:4812`, `server.js:4825` — `previewError(res,port,msg)` interpolates raw `req.params.port` into `title`, `hint`, and `curl` HTML with `Content-Type: text/html`. `handlePreviewProxy()` calls it on the `!validPreviewPort(port)` path, so `/api/preview/<script>...` reaches the sink. Missing: HTML-escape `port` before interpolation.
- **[critical] `rawPinAllowed()` fail-open on exception** — `server.js:464` — `catch { return true; }` grants raw-PIN trust if `isLoopbackReq()`/`countActiveSessions()` throws. Missing: fail-closed `false`; exception path should deny remote raw-PIN.

### High
- **[high] `POST /api/pin` missing `newPin` disables protection** — `server.js:777` — `let next = typeof newPin === 'string' ? newPin.trim() : ''` maps missing/non-string to `''`, and empty means disable. An authed `{"currentPin":"..."}` with no `newPin` wipes the PIN. Missing: `400` when `newPin` is absent/non-string; only explicit `""` should disable.
- **[high] PIN rotation wipes sessions before persist succeeds** — `server.js:740` — `applyPinRotation()` sets `PIN`, broadcasts, `authSessions.clear()`, `closeInvalidSockets()`, then `persistPinToEnv()`. If the write fails, memory uses the new PIN with `persisted:false` but restart reverts to the old PIN on disk. Missing: persist-first or rollback; divergent memory/disk + destroyed sessions lock out the owner until restart behavior is understood.
- **[high] Instant rotation does not clear stale `pendingPinChange`** — `server.js:781`, `server.js:728` — trusted path at `807` calls `applyPinRotation()` without `clearPendingPinChange()`. A later `POST /api/pin/approve` applies the stale `newPIN`. Missing: clear/invalidate pending on any successful instant rotation.
- **[high] Preview WS outlives PIN change/revoke** — `server.js:3795`, `server.js:3821`, `server.js:5094` — `closeInvalidSockets()` and `wsAuthSweep` iterate only `wss.clients`, never `previewWSS.clients`. `previewUpgradeAuth()` runs once at upgrade. Missing: track preview sockets and close on `applyPinRotation()`/`pushSessionRevoked()`/sweep.
- **[high] Claim file races + weak ownership** — `server.js:3435`, `server.js:5176` — `writeTmuxClaim()` overwrites unconditionally with no locking; two starters both pass the `readTmuxClaim()` check and both sweep. File is in world-writable `os.tmpdir()` with default mode (not `0600` like `.tunnels.json`/`.env`), readable/tamperable by local users. Missing: atomic check-and-set, `0600`, per-UID path.

### Medium
- **[medium] `tmuxClaimLive()` over-/under-trusts** — `server.js:3426` — Linux checks `/proc/pid/cmdline` against broad `/server\.js|webtun/i`; non-Linux falls back to `kill(pid,0)` only, so PID reuse looks live forever and sweeps stay disarmed. Cross-UID `kill(pid,0)` throws `EPERM` and returns `false`, letting a second user steal the claim. Missing: stricter identity, PID-reuse handling on all platforms.
- **[medium] SSRF DNS check covers only first address + IPv6 bracket mismatch** — `server.js:4641`, `server.js:4648` — `dns.promises.lookup()` returns one address; multi-record hostnames are not fully vetted. Verified `new URL('http://[::1]:3000').hostname === "[::1]"`, so `allowed.includes('::1')` never matches and `blockedHosts` entries with/without brackets are partly dead; `isBlockedTunnelIp()` strips brackets but the allow/block lists do not. Missing: `lookup(..., {all:true})` check of every address + normalized bracket handling.
- **[medium] WS spec/code mismatch: 0x02 ping + input cap** — `server.js:3737`, `server.js:4066`, `public/js/terminal.js:125` — header says client `0x00` max 64KB and `0x02` ping, but server slices `0x00` to `1048577` bytes and `ws.on('message')` at `4056` has no `0x02` case, silently dropping client pings. Frontend `sendWsInput()` at `public/js/core.js:590` chunks to ~45KB, so the 1MB cap is backstop-only. Missing: handle or remove `0x02`, align documented cap.
- **[medium] Exit code always zero** — `server.js:4020` — `proc.onExit(() => { ... send(0x01, Buffer.from([0])) ... })` ignores the real code/signal despite protocol `0x01 = exit (1B code)`. Missing: forward actual exit status.
- **[medium] Resize dead check** — `server.js:4069` — `c`/`r` are clamped `2..500` before `if (!c || !r) return`, which is unreachable. Missing: remove dead branch or validate short frames explicitly.
- **[medium] Shared `authRateLimiter` bucket across auth endpoints** — `server.js:183`, `server.js:537`, `server.js:766`, `server.js:817`, `server.js:836` — one 5/10s per-IP limiter guards login, PIN change, approve, and veto together; traffic on one locks out the others. `skipWhenNoPin` also disables throttling entirely when open. Missing: separate buckets per route or documented shared budget.
- **[medium] `wsAuthFails` has no size cap** — `server.js:3753` — unlike `createRateLimiter()` at `165` which caps at 10000 keys, the WS handshake-fail map grows unbounded with per-IP entries, swept only by expiry. Missing: same eviction cap.
- **[medium] `exited` flag is dead** — `server.js:4020`, `server.js:4028` — general `onExit` deletes the map entry before the second tracker sets `entry.exited=true`, so `get()` returns undefined. Reconnect after exit always spawns new instead of reporting exited. Missing: set flag before delete or keep tombstone.
- **[medium] `restartTunnel()` leaks child when URL never arrives** — `server.js:4503` — spawned `proc` is untracked until the regex matches; no timeout/kill if cloudflared never prints a URL. The 30s sweep only tracks entries already in `tunnels`. Missing: timeout + kill, like `POST /api/tunnel` at `4699`.
- **[medium] Unbounded `clipboards` + incomplete expiry** — `server.js:2444` — keyed by token hash/IP with no cap; `getClipboard()` skips entries without `sources` during expiry, so empty entries linger forever. Missing: size cap + delete empty/expired unconditionally.

### Low
- **[low] `previewFileTokens` only pruned on mint** — `server.js:343` — expired tokens linger until the next `mintPreviewFileToken()`; no interval sweep. Missing: periodic prune.
- **[low] Dead self-evict guard** — `server.js:442` — `if (oldest === token) break` inside `issueSession()` never fires because the new token is last in insertion order. Missing: remove dead branch.
- **[low] `loadTunnels()` drops dead silently** — `server.js:4469` — dead entries are filtered in memory but never `saveTunnels()`, so `.tunnels.json` accumulates corpses. Missing: rewrite file after filtering.
- **[low] tmux `execFileSync` without timeout blocks loop** — `server.js:3394`, `server.js:3495`, `server.js:3710` — unlike `spawnRead()` timeouts, all tmux control calls can hang the event loop. Missing: timeouts or async variants.
- **[low] Backend flip orphans sessions** — `server.js:3365`, `server.js:3516` — `getTMUX()` lazily flips null→found mid-run; `GET /api/sessions` then lists only tmux, hiding existing `ptySessions`, and WS routing for the same `sessionId` changes backend. Missing: pinned backend per process or merged listing.
- **[low] Session DELETE always succeeds** — `server.js:3544` — tmux and in-memory paths return `{success:true}` even for unknown ids, unlike `DELETE /api/auth/sessions/:id` (`revoked` flag) and `DELETE /api/tunnel` (`alreadyGone`). Missing: consistent existence feedback.
- **[low] `peekSession()` leaves expired entries** — `server.js:3778` — returns `null` without deleting, so stale sessions linger until the 60s `authSessionSweep`. Missing: delete on peer expiry like `getSession()`.
- **[low] Server byte-slice can split UTF-8** — `server.js:4066` vs `public/js/core.js:590` — frontend splits on char boundaries, server slices bytes at `1048577`, corrupting a trailing multibyte char on crafted large frames. Missing: char-boundary split or decoder with replacement handling.
- **[low] `newPin` trim vs login no-trim** — `server.js:777` vs `server.js:540` — set path trims, verify path uses exact compare, so leading/trailing-space PINs are unsettable but the mismatch is silent. Missing: reject or preserve consistently.
- **[low] `envValue()` systemd gap** — `server.js:694` — values containing both whitespace/`#` and quotes/backslashes are left unquoted and will truncate under systemd `EnvironmentFile`, while the loader does not unescape. Missing: reject such PINs at `POST /api/pin`.
- **[low] HSTS/`Secure` rely on spoofable header** — `server.js:243`, `server.js:4870` — `x-forwarded-proto === 'https'` is honored even when `TRUST_PROXY=false`. Effect is only an extra/missing `Strict-Transport-Security`/`Secure` flag. Missing: gate on trusted proxy.

## Area 2 — Backend File / Git / Search / Tunnel Persistence / Middleware + `lib/`
**Source:** `server.js` file/git/search, `spawnRead/gitErrText`, `redactPaths/safeErr/sendErr`, `DATA_DIR/migrateLegacyState`, `.cmdhist/.tunnels/tunnel-url.txt`, watchdog, rate limiters, `WORKSPACE_ROOT/ALLOW_FULL_FS/pathContained`, history; `lib/cloudflared.js`, `lib/zip-read.js`, `lib/zip-store.js`.

### High
- **[High] Upload hierarchy + disk-fill TOCTOU** — `server.js:1864` — `multer` streams to disk before the 2GB batch total is enforced (`1915`), so chunked/no-`Content-Length` uploads fill disk then delete. Pre-flight `1900` is only a client hint. `destination` preserves `originalname` sub-paths with no depth/count cap, and overwrites same-name files silently.
- **[High] CWD/package-dir cloudflared still executed** — `lib/cloudflared.js:77` — `findCloudflared()` keeps `PKG_ROOT` and `process.cwd()` candidates; with `ALLOW_FULL_FS=true` (default) the File API can plant `./cloudflared`, which is then `chmod`d/`spawn`d on next `POST /api/tunnel`. The `82` warning logs but still returns the hijacked path. Ownership/signature is never checked, only exec-bit + non-world-writable (`isUsableBinary:46`).
- **[High] Tunnel SSRF via non-canonical IPs** — `server.js:4641` — literal check only skips DNS for `^\\d+\\.\\d+\\.\\d+\\.\\d+$`; hex/octal (`0x7f.0.0.1`, `2130706433`), `::ffff:169.254.169.254`, and `[::ffff:...]` miss `isBlockedTunnelIp:3476` (`169.254.`/`fe80:` only) and fall through on `dns.lookup` failure (`catch {}`). When `ALLOW_FULL_FS=true` any such host is then allowed as a tunnel target.
- **[High] Zip-writer total cap only at collect time** — `lib/zip-store.js:160` — `collectZipEntries` caps 1GB/50k (`server.js:1060`), but `ZipStoreWriter.addFile:160` streams with no running-total check, so a file growing between `lstat` and `createReadStream` exceeds 1GB unbounded. `collect` also `lstat`s once then `addFile` re-opens by path, so a file→symlink/FIFO swap archives outside bytes or blocks on FIFO. Comment `server.js:1050` claims TOCTOU-safe but only the collection is capped.

### Medium
- **[Medium] `dead` tunnel flag not persisted** — `server.js:4446` — `saveTunnels` serializes `{id,localUrl,tunnelUrl,createdAt,pid,startKey}` with no `dead`; `loadTunnels:4469` resurrects every entry alive-checked. The 5-attempt give-up (`4578`) is therefore lost on restart and retried 5 more times per boot, forever. `tunnelRestarts` is also memory-only.
- **[Medium] `restartTunnel` has no timeout/single-flight** — `server.js:4503` — on sweep-triggered restart the old `proc` is killed but the replacement waits indefinitely for `trycloudflare.com` on stdout/stderr with no timeout. A hanging `cloudflared` leaks a process per backoff tick and the sweep can spawn multiples for the same `localUrl`. `POST /api/tunnel:4698` has a 15s race, the sweep path does not.
- **[Medium] Shared `DATA_DIR` files racy across instances** — `server.js:4451` — `.tunnels.json`, `.cmdhist.json:2548`, `tunnel-url.txt:4463`, `.env:714` all use tmp+rename with no lock/merge. Two servers sharing `~/.config/webtun` (different `PORT`) overwrite each other; last writer wins and tunnels/history are lost. `tunnel-url.txt` is also written world-readable (`4464`, no `0600` unlike siblings).
- **[Medium] History loaded before legacy migration** — `server.js:2556` — `loadCmdHistory()` runs at import, but `migrateLegacyState:660` runs later in `startServer()`. First boot after upgrade reads empty new-location history, then migrates the legacy file without reloading; the next `saveCmdHistory` overwrites the migrated data.
- **[Medium] `GET /search` fan-out + no sandbox file check** — `server.js:1304` — `asyncSafeWalk` does `Promise.all` over all matching files and all subdirs recursively with no concurrency cap, no `visited` set, no `/proc|sys|dev` exclusion. Single-char `q:4107` over depth 4 fans out thousands of `stat` promises. Symlink files use `stat:1316` (follow) with no `WORKSPACE_ROOT` containment, leaking outside metadata.
- **[Medium] Git status 200 vs 501 inconsistency** — `server.js:2738` — `GET /git/status` returns `200 {git:false}` when `git` is missing, while every other git route returns `501 git not installed` (`2797,2821,2854…`). Clients branching on status code per `AGENTS.md` ("missing git is 501") mis-handle status. `gitRootFor:2626` 404-vs-501 ordering is also status-only.
- **[Medium] `GET /git/diff` allows repo-root diff** — `server.js:2801` — validates `pathContained(root,abs)` but unlike `gitFileArgs:2846` never rejects `rel=='.'` (`sub/..` tricks). `?file=.` runs `git diff -- .` over the whole repo (capped only by `maxBytes:400000`). `POST /hunks:3268` rejects root, diff does not.
- **[Medium] Branch/tag `switch` without `--` separator** — `server.js:2962` — `git switch <branch>` / `switch -c <branch>:2975` rely solely on `check-ref-format --branch`. A name that slips validation is parsed as a flag. `tag -d:3219` mitigates with explicit leading-`-` reject (`3173`); branch path (`2930`) has no equivalent guard and no `--`.
- **[Medium] Git error path leaks creds, flattens status** — `server.js:2973` — `gitErrText:973` redacts only filesystem paths, not remote URLs/tokens in `pull/push/fetch` stderr (e.g. `https://<token>@host`). All such failures return `400` (`2905,2922,3111`) whether timeout, auth, or network, so callers cannot distinguish retryable errors. `spawnRead:4162` rejects `new Error(stderr)` which is empty on timeout-kill, degrading to generic `Operation failed` via `safeErr:961` on non-`gitErrText` routes.
- **[Medium] Timeout mismatch orphans git children** — `server.js:2904` — `pull/push/fetch` use `timeout:60000` while `AGENTS.md` documents frontend `api()` 30s cap (90s raw fetch only for fetch). Client aborts at 30s, server keeps `git` until 60s. Other routes scatter `5000` (default `4128`), `15000` (`3233,3272`), `20000` (`2745`) with no documented rationale; large-repo `diff` (no timeout → 5s default) spuriously 500s.
- **[Medium] `redactPaths` misses non-ASCII/space paths** — `server.js:944` — POSIX pattern requires `[\\w.@%+-]+` (ASCII-only) per segment, so `/home/u/документ` or `C:\\Program Files\\…` (`949` stops at space) partially redacts and leaks the remainder (`<path> Files\\…`). `~`-rooted and already-relative leak paths are never redacted. `safeErr:965` also echoes `code` (e.g. `ENOENT`) which is fine, but `gitErrText` bypasses `safeErr` entirely.
- **[Medium] Tar validation skipped on empty listing** — `lib/cloudflared.js:266` — `if (list.stdout) validateTarListing(...) else if (status!==0) throw` means `status==0` + empty stdout extracts without any slip check, then `tar xzf tmp -C tmpDir:272` runs. `validateTarListing:362` itself only inspects `tar tvzf` text; a listing/output mismatch between list and extract is not re-checked beyond the `realpath` containment (`280`).
- **[Medium] `keep_both` silently overwrites after 1000 collisions** — `server.js:1444` — loop caps at `counter<=1000` then "fall through to overwrite" per comment `1448`. A 1001-collision chain destroys the destination without `conflict:true` feedback. `mergeDirs:1493` rollback similarly only removes created entries; overwritten pre-existing files cannot be restored (admitted in comment, still data loss).
- **[Medium] No rate limiter on file mutators** — `server.js:183` — only `search:4106`, `git/*`, `search-content:2125`, `preview-token:1742`, `network:2368` use `rateLimiter` (20/10s) / `authRateLimiter` (5/10s). `POST /write`, `/upload`, `/zip`, `/unzip`, `/batch-*`, `DELETE /files`, `/download`, `/tail` are unlimited; `authRateLimiter` is additionally skipped when `PIN` is empty (`161`), leaving the remaining auth endpoints unthrottled on open instances.

### Low
- **[Low] Upload containment check is dead code** — `server.js:1883` — `subPath` is built from `sanitizeUploadSegment` output (no `..`, no absolute, `..`→`_`), so `pathContained(destDir,subPath)` can never fail. The `Invalid upload destination` branch never fires; real risk (parent-dir symlink of `destDir`, `mkdir -p` through links) is unchecked.
- **[Low] `LARGE_JSON_ROUTES` exact-match fragility** — `server.js:258` — only `/api/files/write` gets `12mb`; `/api/files/write/` (trailing slash), case variants, or future large-body routes fall back to `2mb` and surface as generic `Request body too large:281` instead of the route's `Content too large (max 10MB):1728`. 10MB `Buffer.byteLength` guard vs 12MB JSON envelope also means heavily-escaped (e.g. CJK `\\uXXXX`) payloads trip the envelope first.
- **[Low] `processStartKey` Windows gap + Linux parse** — `server.js:4395` — Linux index `rest[19]` is correct only if `comm` contains no `) `; code uses `lastIndexOf(')')` (`4400`) which is right, but Windows returns `null` always, so `sameCloudflaredProcess:4430` degrades to bare `isCloudflaredProcess` and a recycled PID colliding with any `cloudflared` passes as alive.
- **[Low] Zip descriptor entries skip CRC/size validation** — `lib/zip-read.js:124` — when `uncompressedSize==0 && FLAG_DESCRIPTOR`, `validatingStream` disables both checks. A broken/malicious writer's entry is then bounded only by the outer `liveTotal>1GB:1213` counter, not per-entry integrity. `MAX_CD_BYTES:34` (64MB) + `EOCD_SEARCH_MAX:33` are also memory-heavy for a header parse.
- **[Low] `safeZipEntryName` over/under rejects** — `lib/zip-read.js:113` — `startsWith('..')` rejects harmless `..foo`, while `~`, `%2e%2e`, and drive-relative `C:foo` pass (harmless here because `extractZip:1192` re-checks `pathContained`, but the helper's contract implies standalone safety). `zip-store.validateZipName:65` has the mirrored gap (allows `.`, `~`).

## Area 3 — Frontend Terminal / Tabs / File-Tabs Dock / Drafts / Watcher
**Source:** `public/js/terminal.js`, `tabs.js`, `core.js`, `file-tabs.js`, `editor-panel.js`. No TODOs/FIXMEs (`grep` clean).

### Terminal / WS (high)
- **[High] OSC 0/1/2 titles swallowed, tab rename dead** — `terminal.js:145-196` — `processTerminalOutput()` intercepts every `ESC ] … BEL/ST`, handles only `7/133/52`, then drops the rest via `continue`. Shell title sequences never reach xterm, so `term.onTitleChange()` in `terminal.js:438` never fires.
- **[High] Receive-side UTF-8 split corrupts emoji/CJK** — `terminal.js:133` — Each WS frame is decoded with a fresh `new TextDecoder().decode(data)` (no `{stream:true}`). A multibyte char split across `0x00` frames decodes as `�`, the mirror of the send-side bug `sendWsInput()` was fixed for.
- **[High] Split OSC across frames missed + dead `oscBuf`** — `terminal.js:131-144` — `let oscBuf=''` is never read/written; the parser only scans within one message (`indexOf('\\x07')`/`'\\x1b\\\\'`). A fragmented `OSC 7` (cwd) is passed through as garbage and `tab.cwd` goes stale.
- **[High] Pasted commands lost from history** — `terminal.js:416-427,1041-1054` — Both paste paths call `sendWsInput()` directly, bypassing `sendInput()`'s `_currentInput`/`_lastPasteText` tracking. Textarea paste sets `_lastPasteText` but a paste containing `\\n` executes without ever hitting Enter logic; `pasteToTerminal()` never sets it, so the next Enter saves only the typed tail.
- **[High] `session-revoked` leaves WS reconnect loop running** — `terminal.js:246-250` — Handler clears `authToken` and shows PIN screen but never closes tab sockets or clears `reconnectTimer`. Tabs keep reconnecting with an empty token behind the lock screen.
- **[High] `pin-changed` claims re-login but doesn't force it** — `terminal.js:288-292` — Toast says "re-login required" yet `authToken` is kept and sockets stay open. Client keeps using a rotated-out token until the next 401/close, desynced from server.

### Terminal / WS (medium/low)
- **[Medium] Typing while disconnected is silently dropped** — `terminal.js:31-32` — `sendInput` returns early when `ws.readyState!==OPEN` before history/buffer updates. No queue, no toast, and `_currentInput` goes stale; `sendKey()` in `terminal.js:768-774` has the same drop.
- **[Medium] History buffer only understands Backspace/^U/^W** — `terminal.js:65-99` — Ctrl-A/E/K, Alt-F/B/D, Ctrl-K/Y, and cursor edits (arrows are skipped as ESC) aren't modeled, so the saved `addToCmdHist()` text diverges from the real readline line.
- **[Medium] Mobile keys ignore right-clicked tile** — `terminal.js:751-776` — `sendKey()` uses `getActiveTab()` while copy/paste/select/scroll all use `getTermCtxTarget()`. In Tile View the key bar sends to the active session, not the long-pressed tile (TR-02 inconsistency).
- **[Medium] Scroll-mode misses new tabs; select-mode is active-tab-only** — `terminal.js:964-976,942-961` — `toggleScrollMode()` wires only existing `tabs`; tabs created afterwards scroll normally. `toggleTermSelect()` sets `disableStdin`/`textarea.disabled` on the active tab alone, so background tabs stay editable while UI implies selection mode.
- **[Medium] WebGL guard + context-loss teardown** — `terminal.js:390-396` — Gate `tabs.filter(t=>t.term).length<4` is evaluated only at init, so churn can still exhaust the ~16-context limit; `onContextLoss` disposes the addon and removes `querySelector('canvas')`, which can pull the canvas-renderer canvas and leave a blank terminal with no fallback.
- **[Low] Touch auto-enable for mobile keys is dead** — `terminal.js:1215-1217` — Checks `settings.mobilekeys===undefined`, but `core.js:22` defaults it to `false` and `settings.js:17` only overwrites on boolean, so the branch never fires.

### Tabs / restore / DnD
- **[High] Reload always lands on last tab, active tab not persisted** — `core.js:93-95,503-518` — `saveTabState()` stores order/color/pinned but not `activeTabId`; restore iterates in order then `activateTab(lastTab.id)`. A session ending on a middle tab reopens elsewhere.
- **[High] Heavy-viewer position not persisted** — `core.js:94` — `viewState` (pdf page/scale, epub CFI, office scroll/sheet from `file-tabs.js:160-178`) is never saved, so reload loses reading position even though tab-switch preserves it.
